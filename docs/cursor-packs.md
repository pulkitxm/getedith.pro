# Cursor packs

Cursor Packs is the Edith extension (`cursorPacks`, page under Mac Utilities, command `ed cursors`) that applies mouse cursor themes to every app. This page explains where packs come from, how Edith gets them, what a pack contains, how Edith applies and removes one, and what macOS allows.

## Who can use packs

Cursor packs come with an activated Edith licence. The page, `ed cursors ls` and `ed cursors apply` ask the Edith service for the art with the licence this Mac already uses, so nothing else needs to be set up. Without an activated licence the page says so and offers to try again after you activate Edith; it does not keep asking in the background.

## How packs are made

Every pack is generated by the web toolchain in `apps/web/cursor-packs`:

- `roles.ts` is the list of 39 cursor roles, such as `arrow`, `text` and `wait`, with the macOS cursor names each role replaces.
- `families/` holds the drawings. A family draws every role once and produces several colour variants, and each variant is one pack.
- `tags.ts` is the fixed tag vocabulary. Every tag belongs to one group (style, tone, colour, mood, use or motion) and can have synonyms, so a search for "black" finds dark packs.
- `render.ts` renders each role at its scales into one atlas image and writes the pack manifest.
- `validate.ts` rejects packs whose cursors are empty, touch the canvas edge, are hard to see on white or black, have a hotspot away from the drawn tip, or repeat another role.
- `build.ts` writes the library, the card pages and one file per pack.

## How Edith gets packs

Edith never downloads every pack, and art is only delivered on demand:

- The library lists every pack with its name, family, summary, tags, colours and checksums. Edith reads it when the page opens and keeps the last good copy, so the page still opens offline.
- Card images come in pages. A page loads when one of its cards scrolls into view, the next page is fetched ahead of time, and a page is never requested twice at once.
- A pack's cursors download only when you apply it or open it in the editor.
- A customized pack (your own colours or size) is drawn by the service on demand from the `custom` route and downloaded only for the editor preview and when you apply it.

Every answer from the service is bound to the request that asked for it and checked against the size and checksum from the library before Edith uses it. Everything Edith keeps on disk, including the library, card pages, downloaded packs and the copy of your original cursors, is stored encrypted for this Mac only, and art only exists unencrypted in memory while Edith shows or applies it. If a saved file cannot be read, Edith drops it and downloads it again when it is next needed. Edith keeps the applied pack and at most three recently used packs, the applied customized pack and at most three recently applied customized packs, and card pages up to 24 MB, dropping the oldest first. Editor previews stay in memory and are never written to disk.

Nothing in Edith exports pack art: the page, `ed cursors`, `ed invoke` and Edith's logs never return image data or the decrypted pack files.

### Limits

- New packs per licence are limited to 60 in a rolling 24 hours. Opening or applying a pack you already got in that window does not count again. When the limit is reached, Edith says when you can try again, and packs you already have keep working.
- The service may also ask Edith to slow down. Edith then waits until the time the service gives before it asks again.
- Network errors are retried a couple of times with a growing pause. A refusal from the service is never retried automatically.

### Development

Development builds read the service address from `EDITH_CURSOR_PACKS_URL` when it is an `https` address or `http` on `127.0.0.1` or `localhost`; release builds ignore it. `make dev-extension` passes it through when it relaunches the development build, so the local server (`bun cursor-packs/serve.ts` in `apps/web`) can be used with `EDITH_CURSOR_PACKS_URL=http://127.0.0.1:47341/api/v1/cursors/`. The licence is only ever sent to the production service.

## Customizing a pack

A design is a family, and each preset colour is one pack in it. A customization is a recipe: a base pack, zero or more colour overrides and a size.

- The library lists each family's colour controls (`families[].controls`, at most four, such as Fill, Outline or Edge) and each pack's value for every control (`packs[].values`). A library without them still works: the editor then hides the colour rows and only the size can change.
- The size is one of 0.75, 1, 1.25, 1.5, 1.75, 2, 2.5 or 3 times the normal 32 point pointer.
- Colours that equal the preset are dropped, so a recipe that changes nothing is the plain preset and uses `packs/<id>`. Anything else asks `custom?base=<id>&size=<n>&c=<key>:<rrggbb>,...` with the colours in the family's control order. The answer is sealed to `custom:<base>|<size>|<colours>`, and Edith checks the `x-edith-digest` header against the opened container before using it. A custom request counts against the daily pack limit as its base pack.
- Applying a custom recipe registers every cursor at 32 points times the size, with the hotspot scaled the same way, then verifies the arrow as for a preset. The applied recipe is saved with the state, and its container is kept encrypted under a name derived from the recipe, so putting it back after a login or wake never needs the network.

The editor opens from a card's preview, its Customize button or the "+N" colours button. The stage shows eight key pointers on a light and a dark surface at the chosen size, the busy pointer animates for a few seconds after each change and while the mouse is over the stage (never with Reduce Motion), and the Try it here zones show each pointer as the real mouse pointer inside that zone only, without changing the system cursors. The size readout and the slider marks use the same steps the site names, from 0.75x to 3x. Apply, Applied and the progress state share one button frame in the footer, Cancel appears beside it only while a pack downloads, and Reset all goes back to the preset colours and the normal size. Colour and size changes update the preview after a short pause, keep the last preview on screen while the next one loads, and cancel a preview that a newer change replaced.

## Pack format

A manifest has `schema: 1`, the pack `id`, `name`, `family`, `author`, `license`, `canvas: 32`, the atlas size, and `cursors`, keyed by role id. A customized pack keeps the base pack's `id` and adds `size`; when the size is above 1 every role carries 1x, 2x and 4x images so large pointers stay sharp. Each cursor has:

- `hotspot`: the click point in canvas points.
- `frames`: 1 for a still cursor, up to 24 for an animation.
- `duration`: 0 for a still cursor, 0.01 to 1 second per frame for an animation.
- `reps`: one rectangle in the atlas per scale, from 1x, 2x and 4x in ascending order. A rectangle is `32 * scale` pixels wide, and an animation is a vertical strip of its frames, first frame on top, so the height is the width times the frame count.

Atlases and card images are lossless WebP or PNG. Edith checks the image type from its bytes and refuses anything else.

Before anything reaches macOS, Edith checks the schema, the canvas, that every role id is known and `arrow` is present, the frame counts and durations, that hotspots lie inside the canvas, the scales and rectangle sizes, that every rectangle lies inside the decoded atlas, and that the atlas is at most 4096 pixels on a side and matches the size the manifest declares. Which macOS cursors a role replaces comes from the role table in the extension, never from downloaded data, so a pack can only theme known cursors.

## Finding packs

The page shows one card per design. A card has the preview, the design's colours as a single row of dots (when a narrow card cannot fit them all, the rest sit behind a "+N" button that opens the customizer), Apply and Customize. The header stays pinned while the cards scroll and holds the search field and one row of quick filters such as Dark, Pastel or Retro; one filter is active at a time.

The search field matches pack names, tags (with their labels and synonyms), families and summaries. Every word must match, a word can be the start of a longer one, and small typos are forgiven in longer words. Name matches come first, then tags, then families, then summaries, and ties keep the library order. When nothing matches, the page suggests the closest tags. Return opens the best match in the customizer and never applies it.

Nothing on the page moves when a design is applied: Apply, Applied and the progress state share one button frame, the applied design is named beside the search field and marked on its card and its colour dot, and messages (a pointer macOS kept, a paused download limit, Edith not opening at login) float over the bottom of the page and can be dismissed. While the library loads, the page shows placeholder cards of the same size as the real ones. If the library cannot load, or the licence is refused, the page says why and offers Try again.

## Apply, baseline and reset

Applying a pack, from the page or with `ed cursors apply`, runs one at a time and can be cancelled while it downloads:

1. Download and verify the pack, validate it, and cut each cursor out of the atlas.
2. Before the first apply in a login session, save a baseline: every cursor name in the role table that macOS has registered is saved with its size, hotspot, frames, duration and images, and the names macOS has not registered yet are recorded as absent.
3. Register every role under each of its macOS names at 32 by 32 points, or at 32 points times the size of a customized pack.
4. Read the arrow back from `com.apple.coregraphics.ArrowS`, the name macOS draws the visible arrow from, and compare its size, hotspot and image sizes, retrying briefly. If the arrow did not change, Edith restores the baseline and reports an error. Other names macOS refuses are reported without failing the apply.
5. Save the applied pack and a fingerprint of the arrow as macOS returned it.

Reset registers the saved baseline images again, removes the names that were absent, and forgets the applied pack. If the saved baseline cannot be read, Edith keeps the file, forgets the applied pack so it is not put back, and tells you to log out and back in, which gives you the standard macOS pointers.

The theme is live while the arrow macOS returns matches the saved fingerprint. Edith starts the extension at launch while a pack is applied. When the theme is not live at launch, which is what a new login looks like, Edith saves a new baseline and applies the pack again from its saved copy, a few times at most, and never uses the network for it. It checks again, one second after the change, when displays change or the Mac wakes, and applies again only when the theme is not live. Quitting Edith leaves the theme in place.

## What macOS allows

- Animated cursors can have at most 24 frames. macOS rejects 25 or more.
- The visible arrow and I-beam come from `ArrowS` and `IBeamS`. Reading back `Arrow` right after registering it can return the previous image, so Edith verifies `ArrowS`.
- macOS forgets registered cursors when you log out or restart. Edith puts the applied pack back when it launches.
- A custom pointer colour in System Settings > Accessibility > Display > Pointer makes macOS draw its own pointer, so themes do not show. The pack details tell people to reset it there. Edith does not read that setting.
- Some cursor names, such as `com.apple.cursor.7`, do not exist until an app first uses them. Reset removes those again.
- Apps that draw their own cursors, such as some games, editors and remote desktop clients, keep their own pointers.
- Any app on the Mac can read the cursor macOS is currently drawing. That is how macOS works and Edith cannot prevent it.

## Private interface risk

macOS has no public interface for system-wide cursor themes. Edith uses the private CoreGraphics calls `CGSRegisterCursorWithImages`, `CGSCopyRegisteredCursorImages`, `CGSGetRegisteredCursorDataSize` and `CGSRemoveRegisteredCursor`, resolved at run time with `dlsym`. If a future macOS removes a symbol, the page and `ed cursors status` report that cursor themes are not supported instead of failing to load. If a symbol remains but stops working, the arrow read-back fails, Edith restores the saved cursors and reports the error, so a broken interface cannot leave a half-applied theme behind.
